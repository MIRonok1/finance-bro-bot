# Проект: Telegram-бот «Finance bro»

## Что это

Тренажёр для подготовки к интервью в инвестбанкинг и на финансовые позиции.
Публичный продукт на русском языке, аудитория — студенты и джуны, целящиеся
в IB / equity research / корпфин. В перспективе — платная подписка.

Три модуля:
1. **Технические вопросы** — DCF, мультипликаторы, LBO, accounting, M&A-механика.
   Формат: вопрос → ответ пользователя → эталонный разбор → самооценка/проверка.
2. **Быстрый счёт (mental math)** — арифметика под интервью на время:
   проценты, EV/EBITDA в обратную сторону, CAGR, деление в уме, доли рынка.
3. **Симулятор портфеля на данных MOEX** — Фаза 2, отдельный модуль.

Плюс **Telegram Mini App** (Фаза 3, интерактив — Фаза 4). **С Фазы 4 Mini
App — единственное место, где проходят «Технические вопросы» и «Быстрый
счёт»**: сами мини-игры (тап по вариантам, ввод чисел, таймер, стрик)
живут только там, чат-FSM для них удалён из бота. Это НЕ «Mini App теперь
может всё» — модуль «Портфель» остаётся read-only витриной (см. ниже),
покупка/продажа акций так и остаётся только в чате бота, чтобы не
дублировать одну и ту же операцию в двух местах. Живые цены по холдингам
в Mini App доставляются через WebSocket (см. «Стек» ниже) — тоже
read-only, просто не статично.

## Стек — фиксирован, не менять без обсуждения

- Python 3.12
- **aiogram 3.x** (не telebot, не python-telegram-bot)
- **aiosqlite** + чистый SQL. Никакой ORM: схема простая, миграции — нумерованные
  `.sql`-файлы в `migrations/`, применяются на старте по таблице `schema_version`
- `pydantic-settings` для конфига из env
- `httpx` (async) для внешних API
- `anthropic` SDK — **только в админских скриптах**, не в рантайме бота
- Тесты: `pytest` + `pytest-asyncio`
- Форматирование: `ruff format`, линт `ruff check`
- **Mini App (Фаза 3):** `aiohttp.web` для сервера (не FastAPI — держим один
  лёгкий HTTP-стек, а не два) в том же процессе, что и long polling.
  Фронтенд — React + Vite + TypeScript, `webapp/` в корне репозитория.
  На Netrun `webapp/dist` коммитится в git предсобранным (см. «Хостинг»
  ниже) — сборка через Docker-образ формально ещё существует
  (`Dockerfile`), но прод сейчас идёт мимо неё. Роутинг на фронте —
  `HashRouter` (`react-router-dom`), чтобы серверу не нужен был
  SPA-fallback на все пути. Графики — свой минимальный SVG-компонент, без
  Chart.js/Recharts и т.п. (незачем тянуть зависимость под 1-2 типа графика).
- **Интерактив в Mini App (Фаза 4):** квиз/устный счёт — HTTP API поверх
  тех же чистых модулей грейдинга/генерации, что раньше вызывались только
  из чат-FSM (`app/quiz/logic.py`, `app/quiz/answer_parser.py`, `app/srs.py`,
  `app/mental_math/generators.py` — переиспользуются как есть, не
  дублируются). Состояние игровой сессии — в таблицах `quiz_sessions`/
  `mental_math_sessions` (не в памяти процесса: Netrun усыпляет процесс при
  простое, сессия обязана пережить рестарт, тот же принцип, что FSM бота
  на SQLite). Живые цены портфеля — свой WebSocket-эндпоинт
  (`app/webapp/portfolio_ws.py`) поверх собственного быстрого поллинга
  MOEX ISS (`app/portfolio/ws_poll.py`, только по реально просматриваемым
  тикерам — не долбим бесплатный публичный API вхолостую). initData для
  WS передаётся query-параметром, а не заголовком (браузерный WebSocket не
  умеет ставить кастомные заголовки на handshake) — узкое, явно
  задокументированное исключение из «никакой сессионной куки/JWT» ниже, не
  новый механизм авторизации.

## Хостинг: Netrun (netrun.io) — жёсткие ограничения

- **Единственное постоянное хранилище — папка `/data`.** Всё, что записано вне
  `/data`, пропадает при следующей публикации кода. БД обязательно живёт по пути
  из env `DB_PATH`, дефолт `/data/bot.db`. Никогда не пиши БД, логи или кэш
  в корень проекта или в `./`.
- Локально путь переопределяется через `DB_PATH=./local.db` в `.env`.
- Бот работает через **long polling**, не вебхук — это не меняется.
  Но с Фазы 3 в том же процессе поднимается **aiohttp-сервер** для
  Mini App (статика + `/api/*`), слушает `$PORT` (Netrun должен его
  прокидывать; локальный дефолт — `8080`, см. `WEBAPP_PORT`). Публичный
  HTTPS-домен на входящий порт **пока не проверен вживую** — следующий
  шаг после деплоя: «Мне нужна ссылка» в панели Netrun → открыть
  `<домен>/healthz`, убедиться что отвечает, прежде чем регистрировать
  Mini App в BotFather.
- Все секреты — через переменные окружения (в панели Netrun это «Секреты»,
  формат «Ключ-значение», имя файла `.env`). В коде и в git не должно быть
  ни одного токена. `ADMIN_IDS` — числовой Telegram id, не `@username`
  (проверено вживую: код правильно валит старт с понятной ошибкой при
  username вместо числа — это защита, а не баг).
- Логи — в **stdout** через `logging`, платформа их собирает. Не писать в файл.
- Автоперезапуск платформенный: процесс должен корректно падать при фатальной
  ошибке (не глотать исключения в бесконечном цикле) и подниматься с нуля,
  восстанавливая состояние только из БД. **Никакого состояния в памяти,
  которое нельзя потерять.** FSM aiogram — на SQLite-стораже, не в MemoryStorage.
- **Проверено вживую: `/data` монтируется персистентно автоматически**,
  отдельно настраивать volume не пришлось.
- **Проверено вживую и важно: в GitHub-флоу Netrun НЕ собирает по
  `Dockerfile`** — деплоит через автодетект как обычное Python-приложение
  (`pip install -r requirements.txt`, без Node-стадии). Поэтому
  **`webapp/dist` коммитится в репозиторий предсобранным** (исключение из
  `.gitignore`) — при любом изменении `webapp/src` нужно вручную
  `cd webapp && npm run build` и закоммитить `webapp/dist` заново, иначе
  на проде останется старая версия. `Dockerfile` в репе оставлен (пригодится
  для локальной сборки/если Netrun добавит поддержку Docker), но текущий
  прод-путь идёт мимо него — не полагайся на то, что он реально используется.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `DB_PATH` | нет | путь к SQLite, дефолт `/data/bot.db` |
| `ADMIN_IDS` | да | Telegram user id админов, через запятую |
| `ANTHROPIC_API_KEY` | нет | только для генерации контента оффлайн |
| `PAYWALL_ENABLED` | нет | дефолт `false` |
| `LOG_LEVEL` | нет | дефолт `INFO` |
| `WEBAPP_URL` | нет | публичный HTTPS-адрес Mini App; без него кнопка запуска в боте скрыта |
| `WEBAPP_PORT` / `PORT` | нет | порт aiohttp-сервера, дефолт `8080`; `PORT` (если задан платформой) в приоритете |

Приложение должно падать на старте с внятным сообщением, если обязательная
переменная не задана. Не запускаться с пустым токеном.

## Правило корректности контента — самое важное в проекте

Это тренажёр по финансам. **Неверный «правильный ответ» — критический баг,
хуже падения бота.** Отсюда:

1. **В mental math модель не участвует.** Генерируются только числовые
   параметры задачи; правильный ответ вычисляется кодом на Python из этих
   параметров. Формулы покрыты юнит-тестами.
2. **Технические вопросы приходят из курируемого банка.** Claude может
   генерировать вариации формулировок и дистракторы, но **только оффлайн,
   через админский CLI**, и результат ложится в БД со `status='draft'`.
   Выдача пользователям — исключительно `status='approved'`.
3. **Рантайм бота никогда не вызывает LLM.** Ни одного вызова
   Anthropic API из хендлеров. Это правило про стоимость, латентность
   и корректность одновременно.
4. Числовые ответы сверяются с допуском (`tolerance_pct`), а не на равенство.
   Парсер ответа принимает `1,5`, `1.5`, `1 500 000`, `1.5 млрд`, `1,5bn`.
5. Все денежные величины внутри — `int` в копейках или `Decimal`.
   **Никогда `float` для денег.**

## Общие правила кода

- Часовой пояс — `Europe/Moscow` для всех дат, видимых пользователю. Хранение — UTC.
- Все пользовательские тексты — в одном модуле `app/texts.py` как константы.
  Не разбрасывать русские строки по хендлерам: понадобится английская версия.
- Каждый хендлер оборачивается в общий error middleware: пользователю —
  вежливое сообщение, в лог — трейсбек с `user_id`.
- Не создавай абстракции «на будущее». Один модуль = одна ответственность,
  плоская структура, минимум слоёв.
- После каждой вехи — `ruff check`, `pytest`, и краткий отчёт: что сделано,
  что осталось, где ты принял решение за меня.

## Чего НЕ делать

- Не добавлять Redis, Postgres, Celery, Docker Compose, Alembic, FastAPI,
  отдельную веб-админку — ничего этого в проекте нет. Mini App —
  исключение (Фаза 3, см. выше), но именно на `aiohttp.web`, не на FastAPI.
- Не делать вебхуки (ни для бота, ни выдумывать их для Mini App —
  initData валидируется на каждый запрос, никакой сессионной куки/JWT;
  единственное узкое исключение — WS для живых цен портфеля получает
  initData через query-параметр вместо заголовка по техническим причинам
  браузера, но проверяет той же функцией, см. «Стек» выше).
- Не вызывать LLM в рантайме.
- Не добавлять в Mini App торговые операции (buy/sell) — это остаётся
  только в чате бота, см. описание модулей выше. Это правило **не**
  распространяется на квиз/устный счёт — с Фазы 4 они, наоборот,
  интерактивны только в Mini App, не в чате.
- Не писать больше 3–4 файлов за один ответ без остановки на ревью.
- Не придумывать финансовые данные, котировки или «типичные мультипликаторы»
  по памяти. Если нужны цифры — либо из MOEX ISS API, либо помечай `TODO: verify`
  и спрашивай меня.
- Не коммитить `.env`, `*.db`, `__pycache__`.
