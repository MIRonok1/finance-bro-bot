# Finance bro

Telegram-бот-тренажёр для подготовки к интервью в инвестбанкинг и на другие
финансовые позиции. Правила разработки — в [CLAUDE.md](CLAUDE.md).

## Запуск локально

Требуется Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Заполни `.env`:
- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `ADMIN_IDS` — твой Telegram user id (узнать можно у [@userinfobot](https://t.me/userinfobot))
- `DB_PATH=./local.db` — локально БД лежит рядом с проектом, не в `/data`

### Получить BOT_TOKEN у BotFather

У BotFather нет API — это единственный шаг во всём деплое, который нельзя
автоматизировать, только руками в чате:

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введи отображаемое имя (например, `Finance bro`).
3. Введи username, обязательно оканчивается на `bot` и должен быть свободен
   (например, `finance_bro_bot` — если занят, BotFather предложит попробовать
   другой).
4. BotFather пришлёт токен — вставь его в `BOT_TOKEN` в своём `.env`
   (не отправляй его никуда за пределы своей машины/секретов Netrun).

Список команд, короткое и полное описание бота **настраивать в BotFather
руками не нужно** — бот выставляет их сам через Bot API при каждом старте
(`app/bot_profile.py`, вызывается из `main.py`). Правь тексты и список команд
там же в коде, а не через `/setcommands` в чате с BotFather — иначе изменения
потеряются при следующем деплое.

Регистрация через `/newapp` (см. «Mini App» ниже) — отдельный шаг, нужен
только после первого деплоя, когда появится `WEBAPP_URL`.

Собери фронтенд Mini App (нужен Node.js 20+):

```bash
cd webapp && npm install && npm run build && cd ..
```

Без этого шага бот всё равно запустится, но `/healthz` и `/api/*` будут
отвечать, а сам Mini App — нет (в логах будет предупреждение).

Запуск:

```bash
python main.py
```

Бот работает через long polling — ничего дополнительно поднимать не нужно.
Рядом в том же процессе поднимается aiohttp-сервер Mini App на `WEBAPP_PORT`
(дефолт `8080`).

| Переменная | Обязательна | Назначение |
|---|---|---|

| `ADMIN_IDS` | да | Telegram user id админов через запятую |
| `DB_PATH` | нет | путь к SQLite, дефолт `/data/bot.db` |

| `WEBAPP_PORT` / `PORT` | нет | порт aiohttp-сервера Mini App, дефолт `8080`; `PORT` (если задан платформой) в приоритете |

## Модули

- **📚 Теория и кейсы** — банк вопросов (DCF, мультипликаторы, LBO, accounting,
  M&A). **С Фазы 4 проходится только в Mini App** (`/theory/play`) — тап по
  вариантам (mcq), ввод числа с допуском (numeric), свободный ответ +
  самооценка (open); интервальное повторение слабых мест (упрощённый SM-2)
  доступно оттуда же по кнопке из `/stats`. В чате бота — только текстовая
  сводка (`/stats`), сама тренировка в чат-FSM больше не встроена.
- **🧮 Быстрый счёт** — генератор задач на арифметику (без LLM, чистый Python):
  процент от числа, обратный EV/EBITDA, CAGR, дельта маржи, разводнение доли,
  простой NPV. **С Фазы 4 — тоже только в Mini App** (`/mental-math/play`):
  таймер (считается на сервере, не доверяем клиенту), стрик, чекпоинт каждые
  10 задач.
- **📈 Портфель** — симулятор на данных MOEX ISS (Фаза 2): виртуальный
  капитал, покупка/продажа по живым котировкам с TTL-кэшем, лимит на сделку,
  дневной P&L и сравнение с IMOEX. **Покупка/продажа — только в чате бота**,
  сознательно не продублирована в Mini App (см. CLAUDE.md). **Требует egress
  до `iss.moex.com`** — проверяется через `scripts/doctor.py`.

## Mini App (Фаза 3, интерактив — Фаза 4)

С Фазы 4 Mini App — не просто витрина: квиз и устный счёт полностью
интерактивны и живут только там (чат-FSM для них удалён). Портфель
осознанно остался read-only (никакой торговой логики в Mini App), но
получил живые цены по WebSocket. Открывается кнопкой «☰ Приложение» рядом
с полем ввода, кнопкой «🖥 Открыть приложение» в главном меню, или прямыми
кнопками «📚 Теория и кейсы»/«🧮 Быстрый счёт» (ведут сразу в
соответствующую мини-игру).

- **Стек:** React + Vite + TypeScript, `webapp/`. Роутинг — `HashRouter`
  (`react-router-dom`), поэтому серверу не нужен SPA-fallback.
- **Дизайн:** строгий чёрно-белый минимализм (см. `webapp/src/styles/global.css`)
  — ни одного цветного акцента, направление P&L показывается глифом ▲/▼,
  а не цветом; календарь активности и live-индикатор цены — тоже только
  заливкой/пульсацией, без цвета. Поддерживает светлую и тёмную тему устройства.
- **Разделы:** Профиль (привязка к Telegram identity через initData,
  Duolingo-style календарь активности за 28 дней), Теория и кейсы (прогресс
  по темам + запуск сессии), Быстрый счёт (график точности за 14 дней +
  выбор сложности), Портфель (P&L, сравнение с IMOEX, график equity за
  30 дней, список позиций с живыми ценами).
- **Игровые сессии** (`/theory/play`, `/mental-math/play`) — состояние
  хранится в БД (`quiz_sessions`/`mental_math_sessions`, миграция 010), не в
  памяти процесса: Netrun усыпляет процесс при простое (см. «Статус» ниже),
  сессия должна пережить рестарт/резюмироваться по `?session=<id>` в URL.
- **Живые цены портфеля** — `WebSocket` на `/api/portfolio/ws`, initData
  передаётся query-параметром (браузерный `WebSocket` не умеет ставить
  кастомные заголовки на handshake), проверяется той же функцией, что и
  обычные запросы. Сервер поллит MOEX ISS раз в ~10 секунд, но только по
  тикерам, которые кто-то реально сейчас смотрит.
- **Графики** — свой минимальный SVG-компонент (`webapp/src/components/LineChart.tsx`),
  без Chart.js/Recharts.
- **Бэкенд:** `app/webapp/` — `aiohttp.web` в том же процессе и event loop,
  что и long polling бота (см. `main.py`). Не FastAPI — держим один лёгкий
  HTTP-стек.
- **Авторизация:** каждый запрос к `/api/*` несёт заголовок
  `Authorization: tma <initData>` (кроме WS, см. выше); бэкенд проверяет
  HMAC-подпись по документированному алгоритму Telegram (`app/webapp/auth.py`)
  — никаких сессий/куки/JWT.

**Важно:** initData-валидация (включая WS-вариант через query) не проверена
вживую реальными подписанными данными от Telegram-клиента, кроме уже
подтверждённого раунд-трипа для обычных `/api/*` (см. «Статус» ниже) — сами
интерактивные игровые сессии и live-цены по WebSocket ещё не проверены с
настоящим клиентом.

### Регистрация Mini App в BotFather

1. `/newapp` → выбери бота → укажи `WEBAPP_URL` как URL приложения.
2. Убедись, что `<WEBAPP_URL>/healthz` отвечает `{"status": "ok"}` **до**
   регистрации — если Netrun не проксирует порт наружу, кнопка в боте
   будет вести в никуда.
3. Перезапусти бота с заданным `WEBAPP_URL` — кнопка меню появится
   автоматически при старте (`bot.set_chat_menu_button`).

## Деплой на Netrun

1. Создай приложение на [netrun.io](https://netrun.io), укажи этот репозиторий
   (GitHub, ветка `main`).
2. В «Секретах» создай файл `.env` (формат «Ключ-значение») с переменными
   из таблицы выше. `DB_PATH` **не задавай** — используется дефолт
   `/data/bot.db`. `ADMIN_IDS` — **числовой** Telegram id (узнать у
   [@userinfobot](https://t.me/userinfobot)), не `@username` — при username
   бот падает на старте с понятной ошибкой в логах, это отработавшая защита,
   не баг.
3. `/data` монтируется Netrun как персистентная папка автоматически, ничего
   отдельно настраивать не нужно — **проверено вживую** (вкладка «Данные»
   в панели проекта показывает файлы БД после первого старта).
4. **Важно (проверено вживую, отличается от исходного плана):** Netrun в
   этом флоу (GitHub → автозапуск) **не использует `Dockerfile`** — деплоит
   через автодетект как обычное Python-приложение (`pip install -r
   requirements.txt` + запуск). Значит Node-стадия сборки фронтенда не
   выполняется. Поэтому **`webapp/dist` закоммичен в репозиторий as-is**
   (исключение из `.gitignore`, см. комментарий там) — Netrun просто находит
   готовые файлы. **Если меняешь что-то в `webapp/src` — пересобери и
   закоммить `webapp/dist` заново** (`cd webapp && npm run build`), иначе
   на проде останется старая версия фронтенда. `Dockerfile` в репозитории
   оставлен (пригодится для локальной сборки или если Netrun добавит
   поддержку Docker), но реальный прод-деплой сейчас идёт не через него.
5. Бот работает через long polling — вебхук не нужен. Но с Фазы 3 нужен
   **входящий** HTTP на `WEBAPP_PORT`/`PORT` для Mini App — в панели
   проекта нажми «Мне нужна ссылка», чтобы получить публичный домен, и
   открой `<домен>/healthz` — должен ответить `{"status": "ok"}` **до**
   того, как задавать `WEBAPP_URL` и регистрировать Mini App в BotFather.
6. Для приёма оплат Stars отдельная настройка на стороне Telegram не нужна —
   `sendInvoice` с `currency="XTR"` работает без provider-токена.

## Диагностика окружения (doctor)

После деплоя запусти вручную (в консоли/шелле Netrun):

```bash
python scripts/doctor.py
```

Скрипт проверяет и печатает статус OK/FAIL по каждому пункту:
- версию Python и список пакетов
- существование и доступность на запись `/data`, свободное место
- запись/чтение SQLite в `/data`
- HTTP-доступ до MOEX ISS API (`https://iss.moex.com/iss/engines.json`)
- HTTP-доступ до Anthropic API (если задан `ANTHROPIC_API_KEY`)
- часовой пояс (`TZ`) и текущее время в UTC / Europe/Moscow

От результатов зависит, реализуемы ли на этом хостинге модуль «Портфель»
(нужен egress до MOEX) и `scripts/generate.py` (egress до Anthropic API).
**Важно:** структура ответа MOEX ISS в `app/portfolio/moex_client.py`
основана на публичной документации, а не проверена вживую (см. `TODO: verify`
в файле) — сверь с реальным ответом после первого успешного `doctor.py`.

## Оффлайн-генерация контента

```bash
ANTHROPIC_API_KEY=... python scripts/generate.py --sample-id 3 --count 5
python scripts/generate.py --sample-id 3 --count 5 --dry-run   # без записи в БД
```

Берёт approved-вопрос как образец, просит модель сделать N вариаций,
валидирует структуру и пишет в БД со `status='draft'`. Ни один draft не
попадает пользователям — их проверяет админ через `/review` в боте.

## Статус

Вехи 0–6 плюс Mini App (Фаза 3, интерактив — Фаза 4) реализованы: скелет и
диагностика окружения, банк вопросов, mental math, прогресс и интервальное
повторение, оффлайн-генерация контента через Claude с ручной проверкой,
симулятор портфеля на MOEX, пейволл на Telegram Stars, Telegram Mini App
(React + Vite, чёрно-белый минимализм). С Фазы 4 — квиз и устный счёт
полностью интерактивны только в Mini App (чат-FSM удалён), Duolingo-style
календарь активности (28 дней, `user_activity_days`), живые цены портфеля
по WebSocket. Полный список решений, принятых без уточнения у автора — в
истории чата с Claude Code (CLAUDE.md → «после каждой вехи ... где ты
принял решение за меня»).

**Проверено вживую на Netrun (2026-08-12):** бот успешно деплоится и
поднимает long polling в проде (`@Financebro_investbot`), `/data`
монтируется персистентно автоматически, секреты через панель работают.
**Обнаружено при деплое:** Netrun не использует `Dockerfile` в GitHub-флоу,
деплоит как обычное Python-приложение — поэтому фронтенд Mini App теперь
коммитится в `webapp/dist` предсобранным (см. «Деплой на Netrun» выше).
Также вживую подтверждён публичный HTTPS-домен на входящий порт и
initData-раунд-трип для обычных (не-WS) `/api/*` запросов через настоящий
Telegram-клиент (профиль, статистика, портфель read-only).

Не проверено вживую (Фаза 4, добавлено этой сессией — 322 теста через

  не проверен вживую
