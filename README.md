# Finance bro

Telegram-бот-тренажёр для подготовки к интервью в инвестбанкинг и на другие
финансовые позиции. Правила разработки — в [CLAUDE.md](CLAUDE.md).

## Запуск локально

Требуется Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Заполни `.env`:
- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `ADMIN_IDS` — твой Telegram user id (узнать можно у [@userinfobot](https://t.me/userinfobot))
- `DB_PATH=./local.db` — локально БД лежит рядом с проектом, не в `/data`

### Получить BOT_TOKEN у BotFather

У BotFather нет API — это единственный шаг во всём деплое, который нельзя
автоматизировать, только руками в чате:

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введи отображаемое имя (например, `Finance bro`).
3. Введи username, обязательно оканчивается на `bot` и должен быть свободен
   (например, `finance_bro_bot` — если занят, BotFather предложит попробовать
   другой).
4. BotFather пришлёт токен — вставь его в `BOT_TOKEN` в своём `.env`
   (не отправляй его никуда за пределы своей машины/секретов Netrun).

Список команд, короткое и полное описание бота **настраивать в BotFather
руками не нужно** — бот выставляет их сам через Bot API при каждом старте
(`app/bot_profile.py`, вызывается из `main.py`). Правь тексты и список команд
там же в коде, а не через `/setcommands` в чате с BotFather — иначе изменения
потеряются при следующем деплое.

Регистрация через `/newapp` (см. «Mini App» ниже) — отдельный шаг, нужен
только после первого деплоя, когда появится `WEBAPP_URL`.

Собери фронтенд Mini App (нужен Node.js 20+):

```bash
cd webapp && npm install && npm run build && cd ..
```

Без этого шага бот всё равно запустится, но `/healthz` и `/api/*` будут
отвечать, а сам Mini App — нет (в логах будет предупреждение).

Запуск:

```bash
python main.py
```

Бот работает через long polling — ничего дополнительно поднимать не нужно.
Рядом в том же процессе поднимается aiohttp-сервер Mini App на `WEBAPP_PORT`
(дефолт `8080`).

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `ADMIN_IDS` | да | Telegram user id админов через запятую |
| `DB_PATH` | нет | путь к SQLite, дефолт `/data/bot.db` |
| `ANTHROPIC_API_KEY` | нет | только для `scripts/generate.py` — рантайм бота LLM не вызывает |
| `ANTHROPIC_MODEL` | нет | модель для `scripts/generate.py`, дефолт `claude-opus-5` |
| `PAYWALL_ENABLED` | нет | дефолт `false` — включает дневной лимит бесплатных сессий и `/subscribe` |
| `LOG_LEVEL` | нет | дефолт `INFO` |
| `WEBAPP_URL` | нет | публичный HTTPS-адрес Mini App; без него кнопка запуска в боте скрыта |
| `WEBAPP_PORT` / `PORT` | нет | порт aiohttp-сервера Mini App, дефолт `8080`; `PORT` (если задан платформой) в приоритете |

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | регистрация, главное меню |
| `/help` | все | список команд и модулей |
| `/stats` | все | статистика по темам, mental math, дневная серия, повторение (SM-2) |
| `/subscribe` | все | оформить подписку на Stars (только при `PAYWALL_ENABLED=true`) |
| `/admin` | админы | админ-панель |
| `/review` | админы | проверка черновиков вопросов: approve / edit / reject |
| `/refund <user_id> <charge_id>` | админы | возврат оплаты Stars (`refundStarPayment`) |

## Модули

- **📚 Теория и кейсы** — банк вопросов (DCF, мультипликаторы, LBO, accounting,
  M&A), сессии по теме/сложности, интервальное повторение слабых мест
  (упрощённый SM-2, доступно через `/stats`).
- **🧮 Быстрый счёт** — генератор задач на арифметику (без LLM, чистый Python):
  процент от числа, обратный EV/EBITDA, CAGR, дельта маржи, разводнение доли,
  простой NPV. Таймер, стрик, рейтинг по скорости.
- **📈 Портфель** — симулятор на данных MOEX ISS (Фаза 2): виртуальный
  капитал, покупка/продажа по живым котировкам с TTL-кэшем, лимит на сделку,
  дневной P&L и сравнение с IMOEX. **Требует egress до `iss.moex.com`** —
  проверяется через `scripts/doctor.py`.

## Mini App (Фаза 3)

Read-only витрина поверх той же БД, открывается кнопкой «☰ Приложение»
рядом с полем ввода (или кнопкой «🖥 Открыть приложение» в главном меню).
Покупка/продажа акций остаётся только в чате бота — Mini App ничего не
пишет в БД, кроме первичной регистрации пользователя.

- **Стек:** React + Vite + TypeScript, `webapp/`. Роутинг — `HashRouter`
  (`react-router-dom`), поэтому серверу не нужен SPA-fallback.
- **Дизайн:** строгий чёрно-белый минимализм (см. `webapp/src/styles/global.css`)
  — ни одного цветного акцента, направление P&L показывается глифом ▲/▼,
  а не цветом. Поддерживает светлую и тёмную тему устройства.
- **Разделы:** Профиль (привязка к Telegram identity через initData),
  Теория и кейсы (прогресс по темам, слабые места), Быстрый счёт (график
  точности за 14 дней), Портфель (P&L, сравнение с IMOEX, график equity за
  30 дней, список позиций).
- **Графики** — свой минимальный SVG-компонент (`webapp/src/components/LineChart.tsx`),
  без Chart.js/Recharts.
- **Бэкенд:** `app/webapp/` — `aiohttp.web` в том же процессе и event loop,
  что и long polling бота (см. `main.py`). Не FastAPI — держим один лёгкий
  HTTP-стек.
- **Авторизация:** каждый запрос к `/api/*` несёт заголовок
  `Authorization: tma <initData>`; бэкенд проверяет HMAC-подпись по
  документированному алгоритму Telegram (`app/webapp/auth.py`) — никаких
  сессий/куки/JWT.

**Важно:** initData-валидация не проверена вживую реальными подписанными
данными от Telegram-клиента (нет доступа к Mini App-рантайму в среде
разработки) — юнит-тесты подписывают тестовые данные тем же алгоритмом и
проверяют раунд-трип, но это не то же самое, что реальный клиент. Сверь
после деплоя и регистрации в BotFather.

### Регистрация Mini App в BotFather

1. `/newapp` → выбери бота → укажи `WEBAPP_URL` как URL приложения.
2. Убедись, что `<WEBAPP_URL>/healthz` отвечает `{"status": "ok"}` **до**
   регистрации — если Netrun не проксирует порт наружу, кнопка в боте
   будет вести в никуда.
3. Перезапусти бота с заданным `WEBAPP_URL` — кнопка меню появится
   автоматически при старте (`bot.set_chat_menu_button`).

## Деплой на Netrun

1. Создай приложение на [netrun.io](https://netrun.io), укажи этот репозиторий.
2. В «Секретах» задай переменные окружения из таблицы выше.
   `DB_PATH` **не задавай** — используется дефолт `/data/bot.db`,
   `/data` — единственная постоянная папка на Netrun.
3. Убедись, что платформа монтирует volume в `/data` (иначе БД будет
   пропадать при каждом новом деплое).
4. Деплой собирается по `Dockerfile` — двухстадийный: сначала Node.js 20
   собирает фронтенд (`webapp/dist`), потом Python 3.12 (зафиксирован явно)
   копирует его и ставит рантайм.
5. Бот работает через long polling — вебхук не нужен. Но с Фазы 3 нужен
   **входящий** HTTP на `WEBAPP_PORT`/`PORT` для Mini App — убедись, что
   Netrun даёт публичный HTTPS-домен и проксирует его на этот порт
   (**не проверено вживую** — открой `<домен>/healthz` после первого
   деплоя, прежде чем регистрировать Mini App в BotFather).
6. Для приёма оплат Stars отдельная настройка на стороне Telegram не нужна —
   `sendInvoice` с `currency="XTR"` работает без provider-токена.

## Диагностика окружения (doctor)

После деплоя запусти вручную (в консоли/шелле Netrun):

```bash
python scripts/doctor.py
```

Скрипт проверяет и печатает статус OK/FAIL по каждому пункту:
- версию Python и список пакетов
- существование и доступность на запись `/data`, свободное место
- запись/чтение SQLite в `/data`
- HTTP-доступ до MOEX ISS API (`https://iss.moex.com/iss/engines.json`)
- HTTP-доступ до Anthropic API (если задан `ANTHROPIC_API_KEY`)
- часовой пояс (`TZ`) и текущее время в UTC / Europe/Moscow

От результатов зависит, реализуемы ли на этом хостинге модуль «Портфель»
(нужен egress до MOEX) и `scripts/generate.py` (egress до Anthropic API).
**Важно:** структура ответа MOEX ISS в `app/portfolio/moex_client.py`
основана на публичной документации, а не проверена вживую (см. `TODO: verify`
в файле) — сверь с реальным ответом после первого успешного `doctor.py`.

## Оффлайн-генерация контента

```bash
ANTHROPIC_API_KEY=... python scripts/generate.py --sample-id 3 --count 5
python scripts/generate.py --sample-id 3 --count 5 --dry-run   # без записи в БД
```

Берёт approved-вопрос как образец, просит модель сделать N вариаций,
валидирует структуру и пишет в БД со `status='draft'`. Ни один draft не
попадает пользователям — их проверяет админ через `/review` в боте.

```
  db.py             # aiosqlite + миграции, дневная серия активности

  srs.py             # упрощённый SM-2 (интервальное повторение)
  timeutils.py        # даты в Europe/Moscow при UTC-хранении
  texts.py            # все пользовательские тексты (русский)
  middlewares.py       # обработка ошибок, троттлинг
  keyboards.py          # главное меню
  quiz/                  # банк вопросов и движок квиза
  mental_math/             # генераторы задач + FSM-движок
  portfolio/                 # симулятор на MOEX: клиент ISS, логика, БД, фон
  payments/                    # пейволл на Telegram Stars
  admin/                        # /review черновиков
  webapp/                        # Mini App: aiohttp-сервер, API, initData-авторизация
  handlers/                      # хендлеры aiogram по модулям
migrations/          # пронумерованные .sql-миграции (001-009)
scripts/
  doctor.py          # диагностика окружения Netrun
  generate.py         # оффлайн-генерация вариаций вопросов через Claude
webapp/              # фронтенд Mini App: React + Vite + TypeScript
  src/
    pages/           # Профиль, Теория, Быстрый счёт, Портфель
    components/      # NavBar, LineChart, ...
tests/
main.py              # long polling entrypoint + фоновая задача цен MOEX + Mini App сервер
```
